# Неформол (Neforball)

Telegram Mini App. Игрок создаёт своего персонажа из селфи (16-битный пиксельный
спрайт через AI), затем прокачивает его статы, фотографируя других "неформалов"
камерой телефона. В будущем — рейтинг и дуэли между игроками.

## Статус на сейчас

**Готово и задеплоено:**
- Хостинг: GitHub Pages (`gugenshnaps.github.io/neforball/`), автодеплой из `main`
  через `.github/workflows/pages.yml`
- Supabase-проект `neforball` (id `cjisrumpcjeyzteaaueh`), таблицы `players`,
  `sprite_jobs`, bucket `nefory-photos`
- Edge Function `sprite-proxy` — **асинхронная**: сразу отдаёт `job_id` и
  генерирует в фоне через `EdgeRuntime.waitUntil`, клиент опрашивает
  `sprite_jobs` раз в 2 сек до `done`/`error`. Так сделано специально: у
  `gpt-image-2` разброс задержки 5–80+ сек, и мобильные браузеры (подтверждено
  на Telegram iOS) рвут соединение раньше, чем сервер успевает ответить, хотя
  сама генерация к этому моменту уже прошла и была оплачена. Не возвращать
  обратно на синхронную схему без веской причины
- После генерации сервер сам: вырезает фон через remove.bg (секрет
  `REMOVE_BG_API_KEY`; при сбое фолбэк — сырой спрайт) и **сам сохраняет PNG в
  Storage** (`sprites/{job_id}.png`), отдавая клиенту `result_url`. Телефон
  больше не гоняет base64-мегабайты (это была причина повторных "Load failed"
  при сохранении аватара на мобильной сети). `result_b64` остался как фолбэк
- Ключ `OPENROUTER_API_KEY` лежит в секретах функции
- Генерация спрайта: OpenRouter → **`openai/gpt-image-2`** (осознанный выбор
  после сравнения нескольких моделей — см. `sprite-proxy.ts`, `ALLOWED_MODELS`)

**Игровая механика (`app/index.html`):**
- **Онбординг:** первый запуск без персонажа → обязательный экран "сделай
  селфи" → вызов `gpt-image-2` → персонаж создан и сохранён в `players`
  (Supabase, не в памяти вкладки)
- **Главный экран:** персонаж со статами (жизнь/урон/устойчивость к депрессии)
  по центру, нефорбол ниже, кнопка "Начать ловить" под шаром
- **Ловля:** переиспользует камеру + MediaPipe-сегментацию из старой версии
  (только для анимации поимки, сам силуэт нигде не сохраняется — поимка больше
  не создаёт отдельное существо-коллекционку)
- **Анти-лавочка:** поимка засчитывается только если силуэт человека по маске
  MediaPipe занимает ≥8% кадра (`MIN_PERSON_SHARE`), иначе «никого не поймал»
  и попытка не тратится. Если сегментация не сработала (таймаут) — пропускаем
  без проверки. Порог не тюнился на улице, возможно потребует правки
- **Лимит:** 3 попытки в день (сброс по дате в `players.last_active_date`)
- **Награда за поимку:** гарантированно +1 жетон, ~15% шанс на "критическую
  поимку" (+1 к случайной шкале сверху)
- **Магазин:** жетоны тратятся на +1 к шкале или на поднятие потолка шкалы
  выше 10 (цены растут с каждым уровнем — простая формула в `index.html`,
  считать финальным балансом рано, ещё не тестировали на реальных игроках)
- **Декей:** -1/-1/-1 за каждый день простоя сверх 1-дневного грейс-периода,
  не ниже стартовых 5

**Прототип для сравнения моделей** (`app/sprite_test.html`):
- Отдельный инструмент с выбором модели в UI, полезен если понадобится
  тестировать новые модели генерации в будущем — в основной игре модель
  зафиксирована (`gpt-image-2`) напрямую в `sprite-proxy.ts`

## Технические решения, которые уже приняты (не пересматривать без причины)

- **Бэкенд: Supabase**, **хостинг: GitHub Pages**, **распространение: Telegram
  Mini App** через бота
- **Сегментация фона живых людей: MediaPipe Selfie Segmentation**, бесплатно,
  client-side — используется только для анимации поимки, не для итогового
  сохранения фото
- **Генерация спрайта персонажа: `openai/gpt-image-2`** через OpenRouter,
  формат ответа — просим модель рисовать на magenta и вырезаем на canvas
- **Поимка не создаёт отдельных существ-коллекционок** — прокачивает статы
  игрока напрямую + даёт жетоны. Это осознанный отказ от изначальной идеи
  "коллекция покемонов" в пользу "один персонаж, качаемый ловлей"

## TODO / открытые вопросы

- **RLS в схеме сейчас с временными дырами** (`ВРЕМЕННО` в SQL) — нет проверки
  подписи Telegram initData, любой может писать в таблицу `players` и bucket.
  Нормально для теста, но закрыть перед реальным запуском
- Баланс экономики (стоимость апгрейдов, скорость декея, шанс критической
  поимки) — рабочая гипотеза, не проверена на реальных игроках, вероятно
  потребует правки после первого теста
- Рейтинг и дуэли между игроками — не начинали, будущий этап. Как задел уже
  сейчас: статы персонажа реальны и сохраняются, декей создаёт причину играть
  ежедневно даже до запуска PvP
- Анимация спрайта (покачивание/дыхание через CSS) — ещё не реализована
- Таблица `nefory` из старой схемы (существа-коллекционки) больше не
  используется новой механикой — не удалена, но можно считать легаси
