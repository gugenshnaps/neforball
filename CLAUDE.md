# Неформол (Neforball)

Telegram Mini App — коллекционная игра. Изначальная идея: фоткать неформалов
на улице как покемонов. Сейчас идёт разворот (см. "Текущий фокус" ниже) в сторону
фото себя → 16-битный пиксельный спрайт через AI.

Мы (я, Claude в чате claude.ai) довели проект до этой точки в разговоре и теперь
передаём тебе (Claude Code) для реальной сборки/деплоя — в чате у меня нет доступа
к терминалу пользователя, GitHub, BotFather и т.д., поэтому дальше эффективнее
продолжать тут.

## Статус на сейчас

**Готово и работает** (`app/index.html`):
- Полноценный фронтенд игры, ретро-стиль "The Weather Channel" 90-х (закатный
  градиент, обводной шрифт, стеклянные панели, CRT-скан-линии)
- Камера + вырезание фона живого человека через MediaPipe Selfie Segmentation
  (бесплатно, работает в браузере, CDN уже подключён в файле)
- Анимация "поимки" (silhouette летит в шар с эффектом)
- Детальный просмотр карточки (тап → крупное фото + 3 шкалы)
- Telegram Web App SDK уже интегрирован (`tg.ready()`, `tg.expand()` и т.д.)
- Коллекция сейчас живёт **только в памяти вкладки** — исчезает при перезагрузке.
  Это главный пробел для реального теста (см. TODO).

**Прототип, не готов** (`app/sprite_test.html`):
- Тестовый инструмент: фото → 16-битный спрайт через OpenRouter Image API
  (модель `openai/gpt-image-1`), фон убирается client-side через color-key
  (просим модель рисовать на magenta и вырезаем канвасом — дешевле, чем платить
  за "прозрачный вывод")
- Прямой вызов из браузера в OpenRouter упирается в CORS → нужен прокси
  (`backend/sprite-proxy.ts`), он написан, но **ещё не задеплоен**

**Написано, не задеплоено** (`backend/`):
- `sprite-proxy.ts` — Supabase Edge Function, проксирует запрос к OpenRouter
  (ключ OpenRouter должен жить в секретах функции, никогда не в клиенте)
- `schema.sql` — таблица `nefory`, bucket `nefory-photos`, RLS-политики
  (в SQL есть пометки TODO про временные упрощения RLS — see ниже)

## Технические решения, которые уже приняты (не пересматривать без причины)

- **Бэкенд: Supabase** (пользователь уже знаком с интерфейсом, есть free tier)
- **Хостинг фронтенда: любой статический** — обсуждали GitHub Pages / Netlify Drop,
  финальный выбор ещё не сделан
- **Распространение: Telegram Mini App** через бота, не App Store/Google Play
  (осознанный выбор — быстрее, без модерации)
- **Сегментация фона живых людей: MediaPipe Selfie Segmentation**, бесплатно,
  client-side. Не менять на платный API без явной причины.
- **Генерация спрайтов: OpenRouter → openai/gpt-image-1** (~несколько центов
  за спрайт), выбрано осознанно ("качество важнее цены")
- **Формат фона при генерации спрайта:** просим модель рисовать на сплошном
  magenta и вырезаем сами на canvas — не платить за "transparent output"

## Задача прямо сейчас

Пользователь на macOS, Claude Code запущен в десктопном приложении Claude.
У него уже есть аккаунты Supabase и OpenRouter (ключ от OpenRouter пока нигде
не сохранён — попроси у пользователя, если нужен для деплоя секрета).

Предложи пользователю на выбор (не делай молча всё сразу):

1. **Задеплоить `backend/sprite-proxy.ts`** как Supabase Edge Function
   (`supabase functions deploy sprite-proxy`), попросить у пользователя
   OPENROUTER_API_KEY и положить в секреты функции
2. **Применить `backend/schema.sql`** к их Supabase проекту
   (`supabase db push` или через SQL напрямую)
3. **Захостить `app/index.html`** на GitHub Pages или Netlify — уточни, какой
   вариант пользователь предпочитает, мы это ещё не финализировали в разговоре
4. Обновить `app/sprite_test.html`, чтобы использовать реальный URL
   задеплоенной функции вместо плейсхолдера

## TODO / открытые вопросы (не придумывай ответ сам — спроси пользователя)

- **RLS в `schema.sql` сейчас с временными дырами** (см. комментарии `ВРЕМЕННО`
  в файле) — нет проверки подписи Telegram initData, любой может писать в
  bucket. Это нормально для теста, но перед реальным запуском нужно закрыть.
- Коллекция не сохраняется между сессиями в `index.html` — нужно решить,
  подключать ли Supabase к основному приложению уже сейчас или после того,
  как подтвердится генерация спрайтов
- Форк "фото себя → спрайт" vs изначальная идея "фото прохожих" — обсуждали
  переход ко второму как более простому и этичному варианту для проверки
  спроса, финального решения "заменяем совсем" или "делаем оба режима" не было
- Анимация спрайта пока не реализована вообще — договорились делать через код
  (CSS keyframes: покачивание/дыхание), а не просить у AI-модели несколько
  кадров — это следующий шаг после того, как генерация одного спрайта заработает
